THIRD-PARTY SOFTWARE NOTICES AND INFORMATION

CodeBrix.Cryptography is a general-purpose cryptography library for .NET 10:
ASN.1 encoding, symmetric and asymmetric ciphers, digests, MACs, signatures and
key agreement, post-quantum algorithms, TLS and DTLS, OpenPGP, CMS, PKCS, CMP,
CRMF, OCSP, TSP, X.509 certificate and CRL handling, and OpenSSL PEM support.

CodeBrix.Cryptography is a fork of the BouncyCastle.NET (bc-csharp) project.
Substantially all of the source code in this repository is derived from
BouncyCastle.NET, and several components within BouncyCastle.NET are themselves
derived from other separately-licensed open-source projects. Entries 1 to 6
below cover those.

Entries 7 and 8 are different in kind: they are TEST FIXTURES under test-data/,
obtained directly from their own upstreams rather than from BouncyCastle, so
that this repository does not depend on BouncyCastle's separate, unlicensed
bc-test-data repository. Everything else under test-data/ was generated by this
project itself and is covered by this repository's own MIT licence.

Every project listed below is recorded with its license text reproduced in full,
except where the material carries no license because it is a public domain
dedication or US government public information; those cases say so explicitly.

Note that NuGet package dependencies are NOT listed here -- those packages ship
with their own license and notice files, and their source code is not
incorporated into this repository. The library project has no NuGet
dependencies at all. The test project references, for testing only: xunit.v3,
xunit.runner.visualstudio, Microsoft.NET.Test.Sdk, coverlet.collector and
SilverAssertions.ApacheLicenseForever.

   Modifications made in this fork
   -------------------------------
   a. Namespace rename. The root namespace `Org.BouncyCastle` was renamed to
      `CodeBrix.Cryptography`, and each sub-namespace correspondingly (for
      example `Org.BouncyCastle.Crypto.Digests` became
      `CodeBrix.Cryptography.Crypto.Digests`). Public type names, member names
      and signatures are unchanged, so the library is a drop-in replacement for
      the BouncyCastle.Cryptography NuGet package once the namespace prefix is
      updated.

   b. Runtime configuration keys deliberately NOT renamed. The property names
      that consumers set through environment variables -- "Org.BouncyCastle.
      Asn1.MaxDepth", "Org.BouncyCastle.Pkcs12.MaxIterationCount" and the other
      29 keys in Utilities/Properties.cs, Asn1/DerInteger.cs,
      Pkcs/Pkcs12Store.cs and Crypto/Encodings/Pkcs1Encoding.cs -- keep their
      upstream spelling so that an application already configured for
      BouncyCastle.Cryptography keeps working unchanged after the package swap.
      These are the only remaining occurrences of the string "Org.BouncyCastle"
      outside the provenance comments.

   c. Target framework narrowed to net10.0. Upstream multi-targets net6.0,
      netstandard2.0 and net461. Every framework-selection `#if` / `#elif` /
      `#else` / `#endif` block was evaluated for a net10.0 compilation and the
      non-compiling branches removed, along with the directives themselves.
      `#if DEBUG` blocks were left intact.

   d. Block-scoped namespaces converted to file-scoped namespaces, per the
      CodeBrix family layout rules. Where upstream placed `using` directives
      inside the namespace block (the System.Runtime.Intrinsics aliases in the
      _X86 files, and the type aliases in Math/EC/Rfc7748, Math/EC/Rfc8032 and
      Utilities/IO/Compression), those directives were hoisted to the top of the
      file and the five aliases that resolved relatively against the enclosing
      namespace were fully qualified.

   e. Nullable reference types disabled. The `#nullable` directives were removed
      and the four reference-type `?` annotations they enabled (in
      Utilities/Spans.cs) were stripped. The CodeBrix family builds with NRT
      off; no runtime behaviour changes, because those methods already
      null-check at runtime.

   f. Legacy serialization members marked obsolete. .NET 10 reports SYSLIB0051
      for the formatter-based serialization constructors and `GetObjectData`
      overrides that upstream carries for .NET Framework compatibility. Those 60
      members, across 56 exception types, now carry `[Obsolete]` with the
      framework's own wording. The members are still present and still have
      their upstream signatures; only the obsolete marking is new.

   g. Two `#pragma warning disable CA1857` regions. The AES key schedule in
      Crypto/Engines/AesEngine_X86.cs and the rotation helper in
      Crypto/Engines/Salsa20Engine.cs pass loop-carried values to intrinsics
      whose parameters are declared `[ConstantExpected]`. The rule is disabled
      for those two members only, rather than restructuring hand-tuned
      intrinsics code. No other warning is suppressed in the library project
      apart from CS1591 (missing XML doc comments), which upstream also
      suppresses.

   h. Project files replaced. Upstream's crypto/src/AssemblyInfo.cs was replaced
      by an equivalent CodeBrix AssemblyInfo.cs (the same `[assembly:
      CLSCompliant(true)]` and `[assembly: ComVisible(false)]` attributes), and
      an InternalsVisibleTo.cs was added per CodeBrix family convention. The
      upstream .csproj, .sln, strong-name key, signing scripts, CI
      configuration, and the Nerdbank.GitVersioning / SourceLink packaging setup
      are not carried over.

   i. Folder layout derived from namespaces. Files are laid out so that each
      folder matches its sub-namespace (upstream `crypto/src/util`, which holds
      `Org.BouncyCastle.Utilities`, became `Utilities/`; `crypto/src/openpgp`,
      which holds `Org.BouncyCastle.Bcpg.OpenPgp`, became `Bcpg/OpenPgp/`). File
      names are unchanged.

   j. Character encoding normalised. crypto/src/crypto/kems/mlkem/MLKemEngine.cs
      is encoded as Windows-1252 upstream (two typographic quotes in a comment);
      it is UTF-8 here. All files are LF-terminated with no byte-order mark.

   k. Test framework migrated from NUnit 3 to xUnit.v3, as the CodeBrix family
      requires. `[TestFixture]` and the NUnit-only markers were dropped, `[Test]`
      became `[Fact]`, `[TestCaseSource]` became `[Theory]` plus `[MemberData]`
      with a generated `public static IEnumerable<object[]>` companion next to
      each case-source field, `[Explicit]` and `[Ignore]` became xUnit's `Skip`,
      `[OneTimeSetUp]` became a static constructor (or, for AesX86Test, a
      `SkipUnless` predicate), NUnit `TestCaseData` rows became plain `object[]`
      rows, and the NUnit assertion methods were translated to their xUnit
      equivalents. xUnit has no message overload for Equal / Null / NotNull /
      Same, so the message argument was dropped at those call sites; the
      assertion conditions themselves are unchanged.

   l. Test data embedded. The upstream test project embeds crypto/test/data as
      resources under the logical prefix "Org.BouncyCastle.data."; here they are
      embedded under "CodeBrix.Cryptography.data." and the lookup in
      Utilities/Test/SimpleTest.cs was updated to match.

   n. External test fixtures replaced. Upstream's SimpleTest.FindTestResource
      reads from a SEPARATE repository, https://github.com/bcgit/bc-test-data.git
      (about 4.6 GB), which SimpleTest.FindTestDataPath located by walking up
      from the working directory. That repository carries no licence file, so
      none of its content is reproduced here.

      Instead, test-data/ in this repository holds fixtures from three origins:

        * 193 files this project generated for itself using this library --
          ML-DSA / ML-KEM / SLH-DSA sample credentials, CMS SignedData samples,
          the TLS and DTLS certificate and key set across 26 algorithm families,
          deeply-nested ASN.1 stress fixtures and a CMP sample request. The
          generators are in tests/CodeBrix.Cryptography.Tests/TestDataGeneration/.
          These are original works of this project, covered by this repository's
          MIT licence.
        * 11 Ascon known-answer vector files taken from the Ascon team's own
          reference implementation under CC0 1.0 -- see entry 7 below.
        * The NIST PKITS 2011 archive, extracted verbatim -- see entry 8 below.

      FindTestDataPath was rewritten to resolve test-data/ from
      AppContext.BaseDirectory rather than walking up the filesystem, so the
      suite cannot reach outside the repository. The tests that need the
      fixtures this repository cannot redistribute are skipped by default; they
      can be enabled by cloning bc-test-data as a sibling directory and setting
      CODEBRIX_CRYPTOGRAPHY_USE_BC_TEST_DATA=1. See Utilities/Test/BcTestData.cs.

   m. One upstream bug fixed. Crypto/Tests/MLDsaTest.cs asked for the ML-DSA
      context test vectors as "mldsa44Sha512.rsp", "mldsa65Sha512.rsp" and
      "mldsa87Sha512.rsp", but those files are named with a lowercase "s".
      Windows treats the two spellings as the same file, so the mismatch is
      invisible where BouncyCastle develops and is a missing file on any
      case-sensitive filesystem. The three names were corrected to match the
      files. No test logic was changed.

   o. Selected post-2.7.0 upstream changes applied. The following commits from
      the bc-csharp master branch, made after the release-2.7.0 tag this fork is
      based on, were applied by hand (they cannot be cherry-picked, because the
      files here are namespace-renamed and file-scoped):

        75dd9ae1  Fix IPv6 netmask parsing (Asn1/X509/GeneralName.cs)
        5e200d7a  Fix EdiPartyName.ToAsn1Object, which emitted no tags
        54fb6c4b  OpenPgp: reject a second ASCII-armor checksum line per
                  RFC 9580 sec. 6.2, so a repeated one cannot drive
                  ArmoredInputStream.ReadByte into unbounded self-recursion
        c212b5a7  Add Asn1TaggedObject.HasTagNo
        7a5feac5  Add Properties.X509AllowEmptyIssuerCert
        782a50b3  Extra PKCS#12 test case (no bug)

      Their accompanying test changes were applied as well, and none of them
      needs any fixture that is not already present. The pure refactorings on
      that branch were deliberately NOT applied: they change no behaviour, and
      applying them would widen the divergence from the release-2.7.0 baseline
      that the provenance comments in this repository refer to.

   p. Six TLS signature schemes un-skipped. Upstream's
      TlsTestUtilities.FindResourceName13 returns null for
      ecdsa_brainpoolP256r1tls13_sha256, ecdsa_brainpoolP384r1tls13_sha384,
      ecdsa_brainpoolP512r1tls13_sha512, ecdsa_secp384r1_sha384,
      ecdsa_secp521r1_sha512 and sm2sig_sm3, marking them "TODO: Add test
      resources for these" / "TODO[RFC 8998]", so BcTlsCryptoTest.TestSignatures13
      silently skipped them. This fork generates the corresponding credentials
      into test-data/tls/credentials/ and maps the six schemes in
      FindResourceName13 and GetCACertResource, so those signature paths are
      exercised. This is a deliberate divergence from the upstream test utility,
      in the test project only; no library code is affected.

   q. NIST PKITS incorporated, and the certificate-path tests adapted to the
      2011 edition. Upstream reads this data from bc-test-data, which carries the
      ORIGINAL 2001 edition of PKITS ("O=Test Certificates", certificates valid
      2001-2011). NIST no longer distributes that edition; what it publishes now
      is the 2011 edition ("O=Test Certificates 2011", certificates valid
      2010-2030), and every certificate differs between the two.

      The 2011 edition is vendored here (see entry 8 below) and
      Tests/Nist/NistCertPathTest, NistCertPathTest2 and PkitsTest were updated
      to match it. The changes are all about WHEN and WHAT the fixtures say, not
      about what the tests assert:

        * The pinned validation dates were moved inside the new validity window.
          PkitsTest used 1/1/2010 and NistCertPathTest used 1/1/2011; both now
          use 1/1/2020, which is after the deliberately-expired fixtures run out
          (2011-01-01 08:30Z) and well before the good ones do (2030-12-31).

        * Expected revocation and expiry timestamps were updated from the 2001
          edition's values to the 2011 edition's, per test.

        * PKITS 4.1.6 (Invalid DSA Signature Test6) still requires the path to be
          REJECTED, and it is; but in the 2011 edition the deliberate corruption
          leaves the signature BIT STRING non-octet-aligned, so rejection happens
          while the certificate is being decoded rather than when its signature
          is verified. Those two tests now assert that rejection explicitly.

      No test's pass/fail intent was changed, and all 253 pass against the 2011
      data.

   -----------------------------
   Files for the algorithms standardised in NIST SP 800-232 come from the `main`

     test-data/crypto/ascon/asconaead128/LWC_AEAD_KAT_128_128.txt
